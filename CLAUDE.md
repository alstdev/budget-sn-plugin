# CLAUDE.md — інструкції для Claude Code

Плагін-редактор «Бюджет» для Standard Notes. Зберігає бюджет у Markdown-нотатці, яка читається без плагіна.

**Джерело правди — `docs/SPEC.md`.** Перед будь-якою роботою прочитай його повністю. Якщо інструкція тут суперечить SPEC — зупинись і спитай власника.

Спілкування з власником — українською. Код, ідентифікатори, коментарі в коді, повідомлення комітів — англійською. Документація в `docs/` — українською.

---

## 1. Порядок роботи

1. Працюємо **по етапах** з розділу 10 SPEC. Наступний етап — тільки після явного «ок» власника.
2. На початку кожного етапу/задачі: короткий план (що, в яких файлах, які ризики) → чекаєш підтвердження → тільки потім код.
3. Одна задача = одна гілка `stage-N/<short-name>` = один PR у `main`. Прямі коміти в `main` і force-push заборонені. PR не мержиш сам.
4. Не вигадуй API Standard Notes. Якщо поведінку не видно з документації чи коду бібліотеки — перевір фактично (етап 0) або спитай. Невідоме позначай у PR як ⁉️.
5. Змінювати `docs/SPEC.md` — тільки на прохання власника або окремим PR з поясненням.

## 2. Жорсткі правила безпеки (порушення = PR не приймається)

Повна модель загроз — SPEC, розділ 7. Коротко:

**Дані користувача**
- НІКОЛИ не надсилай вміст нотатки нікуди: жодних `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `navigator.sendBeacon`, завантаження картинок/скриптів/шрифтів із зовнішніх адрес, аналітики, телеметрії, сервісів звітів про помилки.
- НІКОЛИ не пиши дані в `localStorage`, `sessionStorage`, `indexedDB`, cookie, Cache API. Стан UI — тільки в `appData` нотатки через міст.
- НІКОЛИ не логуй вміст нотатки, суми, назви, метадані — навіть у debug. Для діагностики — тільки довжини, лічильники, коди помилок.

**Рендер і виконання коду**
- Вміст нотатки рендериться **тільки як текст** (JSX-вузли Preact). Заборонено: `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `dangerouslySetInnerHTML`, `document.write`, `eval`, `new Function`, `setTimeout`/`setInterval` з рядком.
- Markdown нотатки **не** перетворюється в HTML для показу. Парсимо в модель і показуємо модель.
- Жодних inline-скриптів і inline `<style>`. Стилі — CSS-файли з класами. CSP з SPEC 7.3 не послаблювати без окремого PR з обґрунтуванням.
- Плагін не відкриває вікна (`window.open`), не навігує, не створює iframe.

**Міст до SN (`src/bridge/`)**
- Тільки цей модуль працює з `postMessage` / подією `message`.
- Приймати повідомлення тільки від `window.parent` (`event.source === window.parent`), фіксувати origin після першого валідного повідомлення, валідувати структуру вхідних даних.
- Результати перевірки бібліотеки-мосту і будь-які винятки (наприклад, `targetOrigin '*'`) — документувати в `docs/SECURITY-NOTES.md`.

**Цілісність даних**
- Не зберігати нотатку до першого успішного `parse` отриманого тексту.
- Блокувати збереження порожнього результату або зменшення тексту > 30% без явної дії видалення.
- Невідомий вміст зберігається байт у байт. Нерозібраний рядок не видаляється.
- Зміна формату Markdown → підвищення `budget vN` + міграція + тести. Ніколи мовчки.

**Залежності та ланцюжок постачання**
- Рантайм-залежності: тільки `preact` і бібліотека-міст. Нова залежність (навіть dev) — тільки з дозволу власника, з обґрунтуванням у PR (навіщо, мейнтейнери, ліцензія, розмір, чи є postinstall).
- Точні версії, `package-lock.json` комітиться, встановлення тільки `npm ci`.
- `.npmrc`: `ignore-scripts=true`, `save-exact=true`, `min-release-age=3`. Не вимикати.
- Не запускай `npx <пакет>` для пакетів, яких немає в `package.json`.

**CI / GitHub Actions**
- `permissions: contents: read` на рівні workflow; підвищення — тільки в конкретному job.
- Усі сторонні actions — закріплені **повним SHA коміту** з коментарем версії (`uses: actions/checkout@<sha> # v4.x.x`). SHA бери тільки з оригінального репозиторію action.
- `pull_request_target` заборонений. Недовірені значення (`github.head_ref`, назви/тіла PR, issue) — тільки через `env:`, ніколи `${{ … }}` усередині `run:`.
- Деплой на Pages — тільки вручну з `main` і через environment `github-pages` з ручним підтвердженням; тег `v*` і реліз створює сам workflow після підтвердження.

**Публічний репозиторій**
- Ніяких реальних фінансових даних: ні у фікстурах, ні в тестах, ні в скриншотах, ні в прикладах, ні в комітах. Тільки вигадані дані; фікстури починаються з `<!-- FICTIONAL TEST DATA -->`.
- Секретів проєкт не потребує. Не додавай токенів, ключів, `.env` з чимось реальним.
- Якщо власник дасть свою реальну нотатку для перевірки — клади тільки в `local/` (у `.gitignore`), перед комітом перевір `git status`, що там нічого з `local/`.

## 3. Команди

Node — версія з `.nvmrc` (npm ≥ 11.10 потрібен для `min-release-age`). Оновлюй цей розділ, коли додаєш скрипти.

```
npm ci                   # встановлення (скрипти пакетів вимкнені через .npmrc)
npm run dev              # збірка (development) + перегляд тільки на 127.0.0.1:5173
npm run typecheck
npm run lint
npm test
npm run build
npm run check:dist       # скан dist/ на заборонені API і перевірка CSP (SPEC 7.8)
npm run check:workflows  # pin по SHA, permissions, без ${{ }} у run: (SPEC 7.5)
npm audit --audit-level=high
```

`npm run dev` віддає зібраний `dist/` з тією самою CSP, що й продакшн (dev-сервер Vite з HMR потребує WebSocket та inline-стилів, які CSP забороняє). Після змін — перезапуск.

Винятки сканера `dist/` — лише в `scripts/dist-allowlist.json` з точною кількістю і причиною, і запис у `docs/SECURITY-NOTES.md`. Очікувана CSP — `scripts/csp-policy.json`.

Перегляд слухає тільки `127.0.0.1`, ніколи `0.0.0.0`. Для перевірки на телефоні — тільки через задеплоєну тестову версію, не через відкритий порт у мережі.

## 4. Код

- TypeScript `strict`, без `any` (якщо неминуче — `unknown` + валідація).
- Гроші — цілі числа в мінорних одиницях (копійки/центи). Ніяких float у розрахунках. Форматування `uk-UA` — тільки на рівні UI.
- Шаблони розділів — `src/templates/<id>/`, інтерфейс `SectionTemplate` з SPEC 6.3. Новий шаблон = нова тека + рядок у `src/core/registry.ts`. Ядро не змінюється.
- Будь-яка зміна парсера/серіалізатора — разом з тестами round-trip на фікстурах.
- Доступність: справжні `button`/`input`/`label`, `aria-expanded` на спойлерах, цілі дотику ≥ 44 px на мобільному.

## 5. Definition of Done для PR

- [ ] `typecheck`, `lint`, `test`, `build`, `check:dist`, `npm audit --audit-level=high` — зелені
- [ ] нових мережевих викликів, сховищ, `console.*` з даними — немає
- [ ] CSP не послаблена (або окремий PR з обґрунтуванням)
- [ ] нових залежностей немає (або погоджено власником)
- [ ] фікстури вигадані, реальних даних немає
- [ ] SPEC / SECURITY-NOTES / цей файл оновлені, якщо змінилась поведінка
- [ ] опис PR: що зроблено, як перевірено, що ⁉️ лишилось невідомим

## 6. Чого не робити

- Не мержити, не тегувати, не деплоїти без власника.
- Не змінювати налаштування репозиторію GitHub (захист гілок, Pages, secrets) — це робить власник.
- Не видаляти файли чи гілки без явного прохання.
- Не «полегшувати» правила з розділу 2, щоб щось запрацювало. Зупинись і опиши проблему.
