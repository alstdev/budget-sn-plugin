# Встановлення й оновлення

Плагін-редактор «Budget» для Standard Notes. Інтерфейс плагіна — українською, назва в меню SN — англійською.

## Адреса плагіна

```
https://alstdev.github.io/sn-plugin-budget/ext.json
```

Після перейменування репозиторію (`budget-sn-plugin` → `sn-plugin-budget`) стара адреса `https://alstdev.github.io/budget-sn-plugin/ext.json` більше не працює. Плагін, встановлений за старою адресою, треба встановити заново за новою. Нотатки від цього не змінюються: дані лежать у тексті нотатки, а ідентифікатор плагіна (`io.github.alstdev.budget`) той самий, тож прив'язка нотаток до редактора зберігається.

## Встановлення

1. У Standard Notes встановіть плагін за адресою вище — так само, як встановлювали пробний плагін на етапі 0 (шлях у меню залежить від версії SN; див. «Installing plugins» у SPEC, розділ 12).
2. Пробний плагін «Budget hello (stage 0)» можна видалити: його ідентифікатор інший (`io.github.alstdev.budget-hello`), справжній плагін він не зачіпає.
3. Повторіть на кожному пристрої: десктоп, веб, телефон.

## Перший запуск

1. **Спершу — на копії або на новій нотатці** (SPEC 7.2). Для власної нотатки зробіть резервну копію засобами SN.
2. Нова нотатка → редактор «Budget» → «Створити бюджет». Далі борги, накопичення, місяці й шаблон місяця додаються кнопками «+ Розділ» (на телефоні — кругла кнопка «+»).
3. Або впишіть дані руками в Plain Editor за зразком [`docs/SAMPLE.md`](SAMPLE.md) і відкрийте нотатку редактором «Budget».

## Перенесення з Super-нотатки

Автоматичного перенесення немає: Super зберігає нотатки у власному форматі, і перетворення в Markdown відбувається з втратами (SPEC, розділ 2). Порядок:

1. Створіть нову нотатку з плагіном «Budget» → «Створити бюджет».
2. Додайте борги й накопичення кнопками плагіна з поточними сумами як початковими.
3. Додайте постійні витрати й покупки на вкладці «Планування», створіть поточний місяць.
4. Стару Super-нотатку не видаляйте, доки не переконаєтесь, що все перенесено.

## Як працює оновлення

- Нову версію публікує власник: Actions → **Deploy** → **Run workflow** (гілка `main`) → **Approve and deploy**. Версія береться з `package.json`; ту саму версію повторно не опублікує.
- **Веб і телефон** завантажують плагін з адреси вище при відкритті нотатки, тож нову версію отримують після публікації.
- **Десктоп** на етапі 0 працював із локальної копії плагіна (`http://127.0.0.1:…`). ⁉️ Чи оновлює десктоп SN цю копію сам — не перевірено. Якщо після публікації десктоп показує стару версію, видаліть плагін і встановіть заново за тією самою адресою.
- **Автооновлення (`latest_url`) не використовується** — рішення етапу 4 (SPEC 7.6): плагін бачить розшифровані нотатки, тому нова версія потрапляє до них лише після явної публікації власником.
- Для кожної версії GitHub-реліз містить zip (`budget-<версія>.zip`) і `SHA256SUMS` для перевірки.

## Якщо щось пішло не так

- Відкрийте нотатку в Plain Editor: усі дані — звичайний Markdown, їх видно й без плагіна.
- Плагін не зберігає порожній текст і не скорочує нотатку більш ніж на 30% за раз; рядки, які не розібрав, лишає без змін.
- Розділ з помилкою відкривається лише для перегляду; виправте його в Plain Editor.
- Повідомити про вразливість — приватно, через вкладку Security репозиторію (див. README).
