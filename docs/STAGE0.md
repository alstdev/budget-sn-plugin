# Етап 0 — перевірка платформи

Протокол ручних перевірок з SPEC, розділ 3, і таблиця результатів. Пробний плагін — `hello-budget` (`src/hello/`). На етапі 1 його замінить справжній плагін.

> **Лише на окремій тестовій нотатці.** Плагін змінює текст тільки порожньої нотатки або нотатки, яку сам позначив першим рядком `<!-- budget-hello test note: safe to overwrite -->`. Справжню нотатку він лише читає (довжина й відбиток), але відкривати її в ньому не треба.

## 1. Підготовка (один раз, налаштування GitHub)

1. Settings → Pages → Source: **GitHub Actions**.
2. Settings → Environments → `github-pages` (з'являється після вибору Pages source):
   - **Required reviewers** — власник;
   - **Deployment branches and tags** — дозволити тег `v*`; інакше деплой з тегу буде відхилено. ⁉️ Типове правило середовища залежить від налаштувань репозиторію — перевірити на місці.
3. Settings → Branches → правило для `main`: PR обов'язковий, заборона force-push.
4. Settings → Code security: Secret scanning + Push protection, Dependabot alerts.
5. 2FA на акаунті GitHub.

## 2. Публікація

1. Злити PR етапу 0 у `main`.
2. Поставити тег версії з `package.json` і запушити його:

   ```bash
   git tag v0.0.1 && git push origin v0.0.1
   ```

3. Actions → Deploy → підтвердити деплой у середовищі `github-pages`.
4. Після деплою:
   - сторінка: `https://alstdev.github.io/budget-sn-plugin/`;
   - маніфест: `https://alstdev.github.io/budget-sn-plugin/ext.json`;
   - реліз: zip + `SHA256SUMS`.

## 3. Встановлення

На кожному пристрої встановити плагін за URL маніфесту `https://alstdev.github.io/budget-sn-plugin/ext.json`. Шлях у меню — за інструкцією «Installing plugins» (SPEC, розділ 12; він залежить від версії SN). Створити **нову порожню** нотатку, вибрати редактор «Budget hello (stage 0)», натиснути «Позначити порожню нотатку як тестову».

## 4. Перевірки

Після кожної перевірки скопіювати текст із блоку «Звіт» (там немає вмісту нотатки) у таблицю нижче або в чат.

| # | Що зробити | Що записати |
|---|---|---|
| 1 | Відкрити тестову нотатку на десктопі, у вебі, на телефоні | чи відкривається; «Середовище», «Платформа», «Зареєстровано в SN» |
| 2 | На одному пристрої «Додати рядок», дочекатися синхронізації, відкрити на інших | чи збігаються «Довжина» й «Відбиток» на всіх трьох |
| 3 | На телефоні: «Записати 100 КБ», потім 1 МБ, потім 5 МБ; після кожного — закрити й знову відкрити нотатку | «Останнє збереження» (мс), «Від старту до першої нотатки» (мс), чи не падає SN, чи відкривається нотатка в Plain Editor |
| 4 | Перемкнути світлу й темну тему SN | чи змінився вигляд плагіна; «Стилі теми» й «Порушення CSP» (origin) |
| 5 | Два пристрої без мережі, на кожному «Додати рядок», потім увімкнути мережу | що зробив SN: копія-конфлікт чи перезапис; довжина й відбиток на обох |
| 6 | Подивитися блок «Безпека» (особливо на телефоні) | «Повідомлень прийнято», «Відкинуто», «Останнє відкинуте» (причина, `source`, origin) |
| 7 | Увімкнути «Prevent editing» для нотатки | «Заблокована» = так, кнопки неактивні |
| 8 | «Метадані +1», закрити й відкрити нотатку, перевірити на іншому пристрої | лічильник зберігся й синхронізувався |
| 9 | Десктоп/веб: DevTools → Network при відкритті нотатки | лише файли плагіна з `alstdev.github.io`, інших запитів немає |

Якщо пункт 1 провалюється на телефоні, мобільну верстку відкладаємо й переглядаємо рішення разом (SPEC, розділ 3).
